# Workspace Rules: Animus Mundi

## Subagent Roles & Guidelines
- **PM Devil's Advocate (`pm-devils-advocate`):** Whenever an agent completes drafting or major revisions to any Functional Requirements Document (FRD) in `docs/frd/`, the agent must invoke the `pm-devils-advocate` persona (or apply `.agents/skills/pm-devils-advocate`) to red-team the document, publish a severity-ranked punch-list to `docs/audit/pending/[date]-[document].md` (format: `YYYY-MM-DD-[document].md`), and log the evaluation in `docs/audit/audit_registry.md`. Older audits are marked as stale when superseded or when the document updates.
- **PM Audit Reviewer (`pm-audit-reviewer`):** Whenever pending audits exist in `docs/audit/pending/` or upon explicit request (mentioning `@pm-audit-reviewer`), the agent invokes the `pm-audit-reviewer` persona (or applies `.agents/skills/pm-audit-reviewer`) to read active audit punch-lists, formulate concrete potential resolutions, and conduct an interactive dialogue to address findings. Once all items for a given audit are marked as resolved, the persona applies the approved edits to the target FRD in `docs/frd/`, verifies health via `tools/linter/lint_frd.ps1`, deletes the pending audit file from `docs/audit/pending/`, commits the changes, logs completion (date & time, commit hash, and source: manual or agentic) in `docs/audit/audit_registry.md`, and pushes to version control.
- **Permissions & Git Workflow:**
  - `pm-devils-advocate` operates read-only on all specifications and source files, writing only to `docs/audit/`. Upon completing the analysis, the agent commits (`git add docs/audit/`, `git commit`) and pushes (`git push`) to version control.
  - `pm-audit-reviewer` is authorized to modify specification documents in `docs/frd/` to enact approved resolutions, delete resolved files from `docs/audit/pending/`, update `docs/audit/audit_registry.md`, and execute `git add`, `git commit`, and `git push`.
