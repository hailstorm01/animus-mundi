## Goal
Before linting, the pre-commit hook rebuilds `bin/cardtown(.exe)` when it is missing or older than the Go sources, so a commit is never linted by an old binary. If the rebuild fails, the hook says so and falls back to `go run`.

## Inputs
- Hook script and installer: `preCommitHookScript` and `Install` in `pkg/toolchain/hook/hook.go` (`cardtown hook install`).
- Why: after T-0004 the hand-built binary was older than T-0002–T-0004, so every commit since T-0001 was linted with T-0001-era checks (board directive #9).
- Rulings that apply: none.

### Behavior
- **Binary path:** unchanged selection. Use `bin/cardtown.exe` if it exists, else `bin/cardtown`. If neither exists, build to `bin/cardtown$(go env GOEXE)`.
- **Stale:** the binary is older than any `*.go` file under `cmd/` or `pkg/`, or older than `go.mod`. Other files (for example `.md` under `pkg/`, or `.go` outside `cmd/` and `pkg/`) do not make it stale.
- **Rebuild:** `go build -o <binary> ./cmd/cardtown`, run from the repository root. Print one line naming the binary path and why (`missing` or `stale`) before building. A fresh binary prints nothing extra.
- **Build fails:** print the build's own error output, then one line saying the rebuild failed and the hook is using `go run`. Then lint with `go run ./cmd/cardtown lint --staged --repo-root <root>`. Never run the old binary after a failed rebuild.
- **Lint fails:** the hook exits 1 with the existing "Pre-commit linting failed!" message, as today.
- The script stays POSIX `sh` (it runs under Git for Windows' `sh`). `find -newer` is fine; avoid bash-only syntax.

## Acceptance Cases (harness tasks only; written by the lead)
Each case runs in a fixture repository in `t.TempDir()`: `git init`, a `go.mod`, a stub `cmd/cardtown/main.go` that prints a version marker (for example `fixture lint v1`) and exits 0, and a `pkg/` directory with one `.go` file. Call `hook.Install(<fixture>)`, then run `sh .git/hooks/pre-commit` from the fixture root and check the combined output and exit code. Set file times with `os.Chtimes`, never with sleeps. Skip the test (not fail) when `sh`, `git` or `go` is not on `PATH`.
1. **Fresh binary:** build v1, change the source to print v2, then set the binary's time after every source file → output contains `v1`, no rebuild line, the binary's modification time is unchanged, exit 0.
2. **Stale from `cmd/`:** binary built from v1, source changed to v2 and newer than the binary → the rebuild line names the binary path and `stale`, the output contains `v2`, exit 0.
3. **Stale from `pkg/`:** only a `.go` file under `pkg/` is newer than the binary → rebuilt (rebuild line names `stale`), exit 0.
4. **Stale from `go.mod`:** only `go.mod` is newer → rebuilt.
5. **Not stale from other files:** only a `.md` file under `pkg/` and a `.go` file under `tools/` are newer → no rebuild, output contains `v1`.
6. **Missing binary:** no `bin/` directory → the rebuild line names `bin/cardtown<GOEXE>` and `missing`, that file exists afterwards, the output contains the current marker, exit 0.
7. **Broken build:** the binary is stale and `cmd/cardtown/broken.go` has a syntax error → the output contains the compiler error naming `broken.go`, then the fallback line naming `go run`, the old binary's marker does **not** appear, and the hook exits non-zero (because `go run` fails too).
8. **Lint fails:** the stub exits 1 → the hook exits 1 and prints "Pre-commit linting failed!".
9. **Installed copy matches:** after `Install`, `.git/hooks/pre-commit` and `tools/linter/pre-commit` in the fixture hold the same bytes as `preCommitHookScript` (create `tools/linter/` in the fixture first).
