## 1. Executive Summary & Red-Team Assessment

`02_Card_Data_Pipeline_FRD.md` (v1.1) serves as the authoritative modeling bridge between the tabletop rules (`01`), the compiler (`03`), the wire protocol (`04`), and the headless engine (`05`). Stress-testing the declarative AST schemas (`FR-ABL-001`–`FR-ABL-012`), atomic effect primitives (`FR-PRM-001`), and benchmark implementations (`reference/02_Benchmark_Card_Blueprints.md`) against the 167 cards in `data/cards/*.csv` and companion FRDs reveals **one Blocker**, **two High-severity schema conflicts/underdeveloped specs**, **two Medium-severity inconsistencies**, and **one Low-severity cross-FRD redundancy**:
1. **Blocker Gap / Underdeveloped Spec (`DA-DAT-001`):** Five shipped Core Set card mechanics (*Despoiler Worm* opponent card draw, *Steel Rain* bounded `up to 3` discard + per-card targeted damage loop, *Frostfire Breath* / *Echoing Nightmare* prior-step outcome conditions, *Sandstorm Lightbringer* player-chosen destination zone, and multi-hook triggers `"Whenever this unit deploys or attacks"` / `"When this unit deploys or is killed"`) cannot be represented using the properties currently defined in `FR-ABL-002`, `FR-ABL-007`, and `FR-PRM-001`.
2. **High Conflicts (`DA-DAT-002`, `DA-DAT-003`):** `LOOK_TOP_CARDS` in `FR-PRM-001` (`operations: Array<OpDef>`, where `OpDef` is undefined) directly contradicts the `partition: { destinations: [...] }` schema used in `reference/02_Benchmark_Card_Blueprints.md` (#4 *Samsara, Living Tempest*) and lacks fields for *Light of the World Soul* and *Devilhorn Scouting Party*; `CostDef.costType` in `FR-ABL-007` uses `EXHAUST_ASSET` while `05_Headless_Game_Engine_FRD.md` (`FR-ENG-013`) expects `EXHAUST_ALLY`, and `CostDef` conflates self-sacrifice (`"kill this unit"`, requiring no target binding) with allied-asset sacrifice (`"kill an allied unit"`, requiring a `TARGET_ROLE_SACRIFICE_COST` target binding).
3. **Medium Conflicts (`DA-DAT-004`, `DA-DAT-005`):** `FR-ABL-005` cites non-existent opcodes (`SET_INITIAL_READINESS`, `CANCEL_AND_BOUNCE`) absent from `FR-PRM-001`, `FR-PRM-001` uses inconsistent target field names (`targetCard`, `targetAsset` vs. `EffectDef.target`), and `FR-DAT-005` marks `currentProxy` / `needsRework` as optional while `FR-CMP-005` unconditionally serializes them.

*(Note: Game and rule balance design questions are excluded per audit scope.)*

## 2. Severity-Ordered Punch-List

### 🔴 Blocker / Critical
- **[DA-DAT-001] [Gap / Underdeveloped Spec] Missing AST Constructs in FR-ABL-002, FR-ABL-007, and FR-PRM-001 for Five Core Set Card Mechanics**
  - **Requirement Citations:** `FR-ABL-002`, `FR-ABL-006`, `FR-ABL-007`, `FR-PRM-001`, `FR-TRG-007`, `FR-VAL-003`
  - **Vulnerability / Flaw:** `FR-VAL-003` ("Must Fit All") and `FR-CMP-017` require every card in `data/cards/*.csv` to map cleanly to `AbilityDef.schema.json`. However, five Core Set mechanics in `data/cards/*.csv` cannot be modeled using the current sub-schemas in `FR-ABL-002`, `FR-ABL-007`, and `FR-PRM-001`:
    1. *`DRAW_CARD` Missing `targetPlayer` (`Despoiler Worm`)*: `FR-PRM-001` defines `DRAW_CARD` with only `count: ValueToken` (`"Draws cards from owner's deck"`), omitting `targetPlayer: Enum` (unlike `DISCARD_CARD`). This cannot express *Despoiler Worm* (`"When this unit is killed, all opponents draw 2 cards."`).
    2. *Bounded Optional Discard & Per-Card Targeted Iteration (`Steel Rain`)*: `DA-DAT-003` specifies that *Steel Rain* (`"Discard up to 3 cards. For each card discarded this way, deal 2 damage to chosen asset. Then, if you have no cards in hand, draw 2 cards."`) resolves as independent 2-damage targeted iterations per card discarded. However, `DISCARD_CARD` in `FR-PRM-001` has only `count: ValueToken, targetPlayer: Enum` (no `upTo: Boolean` / `maxCount` parameter), and `EffectDef` (`FR-ABL-007`) has no `repeatCount: ValueToken` property to execute $K$ independent targeted `DEAL_DAMAGE` iterations scaled by `CAUSALITY_CONTEXT.DISCARDED_COUNT`.
    3. *Prior-Step Outcome Conditions (`Frostfire Breath`, `Echoing Nightmare`)*: `ConditionDef` and `ValueToken` (`FR-ABL-007`) cannot test whether a bound target was killed by the preceding step (*Frostfire Breath*: `"Deal 2 damage to chosen exhausted non-Scratch asset. If that asset is killed, draw a card."`, because `KILLED_COUNT` is a `ValueToken` property rather than a `ConditionDef` predicate) or whether an entity was returned to hand in the preceding step (*Echoing Nightmare*: `"When this unit deploys, return chosen opposing unit in the Main Theater to its owner's hand. If a unit is returned this way, move this unit to the Main Theater."`, because `RETURNED_COUNT` is missing from `ValueToken.property`).
    4. *Player-Chosen Destination Zone in `MOVE_ZONE` (`Sandstorm Lightbringer`)*: `FR-PRM-001` defines `MOVE_ZONE` with a fixed `destinationZone: Enum` (`RESERVES` or `MAIN_THEATER`), lacking an enum option (e.g., `CHOSEN_ZONE` bound via `TARGET_ROLE_DESTINATION_ZONE` in `FR-MSG-003`) for *Sandstorm Lightbringer* (`"Exhaust: Move chosen allied unit to the Main Theater or Reserves."`).
    5. *Multi-Hook Trigger Preambles (`Fungal Evangelist`, `Spoil Forest Colossus`, `Stardust Colossus`, `Ironclad Colossus`, `Earthshaker Colossus`)*: `FR-ABL-002` defines `triggerHook` as a singular string enum rather than allowing an array of hooks (or specifying whether `"Whenever this unit deploys or attacks"` / `"When this unit deploys or is killed"` compiles into two separate `TriggeredAbilityDef` nodes).
  - **Exploit / Failure Scenario:** Authoring `data/schemas/ast_overrides.json` (`FR-CMP-017`) for these Core Set cards will fail `AbilityDef.schema.json` validation (`ERR_OVERRIDE_SCHEMA_INVALID` in `FR-CMP-022`) or fail execution in `FR-ENG-018`–`FR-ENG-021`.
  - **Remedy:** Update `FR-ABL-002`, `FR-ABL-007`, and `FR-PRM-001` to: (1) add `targetPlayer: Enum [SELF, OPPONENT, ALL_OPPONENTS]` (default `SELF`) to `DRAW_CARD`; (2) add `upTo: Boolean` to `DISCARD_CARD` and `repeatCount: ValueToken` to `EffectDef` for *Steel Rain*; (3) add `RETURNED_COUNT` to `ValueToken.property` (`CAUSALITY_CONTEXT`) and allow `statComparison` / `valueComparison` on `ConditionDef` to compare `ValueToken` expressions (`KILLED_COUNT >= 1`, `RETURNED_COUNT >= 1`); (4) add `CHOSEN_ZONE` to `MOVE_ZONE.destinationZone` (resolved via `TARGET_ROLE_DESTINATION_ZONE`); and (5) allow `triggerHook` in `FR-ABL-002` to accept `String | Array<String>` (or explicitly state that compound trigger preambles emit one `TriggeredAbilityDef` per hook).

### 🟠 High
- **[DA-DAT-002] [Conflict / Underdeveloped Spec] Contradictory LOOK_TOP_CARDS Schema Between FR-PRM-001 and Benchmark Blueprints, and Undefined OpDef / PartitionDestDef**
  - **Requirement Citations:** `FR-PRM-001`, `FR-ABL-007`, `FR-MOD-001`
  - **Vulnerability / Flaw:** In `FR-PRM-001` (line 270), `LOOK_TOP_CARDS` specifies its parameter schema as `count: Integer, operations: Array<OpDef>`, where `OpDef` is never defined anywhere in `02_Card_Data_Pipeline_FRD.md`. Conversely, Benchmark #4 (*Samsara, Living Tempest*) in [`reference/02_Benchmark_Card_Blueprints.md`](file:///c:/Users/blade/animus-mundi/animus-mundi/docs/frd/reference/02_Benchmark_Card_Blueprints.md#L147-L154) does not use `operations` and instead serializes `partition: { destinations: [{ zone: "HAND", count: 1 }, { zone: "DISCARD", count: 1, trackAs: "discardedCard" }] }`. Moreover, neither schema defines how *Light of the World Soul* (`"deploy up to 2 unit cards from among them for free, and put up to 1 of those cards into your hand. Put the rest on the bottom of your deck in any order"`) and *Devilhorn Scouting Party* (`"deploy a unit card with Requisition cost 3 or less from among them for free. Put the rest on the bottom of your deck in any order"`) express `DEPLOY_FREE` destinations, `upTo` counts, card filters (`FilterDef`), and remainder ordering.
  - **Exploit / Failure Scenario:** Benchmark #4 in `02_Benchmark_Card_Blueprints.md` fails validation against `FR-PRM-001`'s `operations: Array<OpDef>` definition, and neither schema can represent *Light of the World Soul* or *Devilhorn Scouting Party*.
  - **Remedy:** Replace `operations: Array<OpDef>` on `LOOK_TOP_CARDS` in `FR-PRM-001` with `partition: { destinations: Array<PartitionDestDef> }` (matching `02_Benchmark_Card_Blueprints.md`), and define `PartitionDestDef` in `FR-ABL-007` with properties: `action` (`MOVE_TO_ZONE` default, or `DEPLOY_FREE`), `zone` (`HAND`, `DISCARD`, `TOP_OF_DECK`, `BOTTOM_OF_DECK`), `count` (`Integer` or `"REMAINDER"`), `upTo` (`Boolean`), `filter` (`FilterDef`), `order` (`"ANY_ORDER"`), and `trackAs` (`String`).

- **[DA-DAT-003] [Conflict / Ambiguity] CostDef.costType Naming Conflict with FRD 05 (EXHAUST_ASSET vs. EXHAUST_ALLY) and Ambiguous Self-Sacrifice vs. Allied-Sacrifice Modeling**
  - **Requirement Citations:** `FR-ABL-007`, `FR-ABL-009`, `FR-DAT-005`
  - **Vulnerability / Flaw:**
    1. *Cross-FRD Enum Conflict*: `FR-ABL-007` (line 224) and `02_Benchmark_Card_Blueprints.md` (#8 *Funeral Fungus*) define the allied exhaustion cost type as `EXHAUST_ASSET`, whereas `05_Headless_Game_Engine_FRD.md` (`FR-ENG-013`, line 409) checks for `EXHAUST_ALLY`.
    2. *Self-Kill vs. Chosen-Ally-Kill Ambiguity*: `FR-ABL-007` lists both `KILL_ASSET` and `SACRIFICE_ALLY` in `CostDef.costType` without defining their difference, while omitting `KILL_SELF` (analogous to `EXHAUST_SELF`). In the Core Set, five cards sacrifice **themselves** as an activation/trigger cost (*Sinuous Growth*, *Boneyard Scavenger*, *Ruin Partisans*: `"kill this unit"`; *Rhapsody's Hollow*, *Blind Defile*: `"kill this structure"`—requiring zero external target bindings), whereas five cards kill a **chosen allied asset** (*Feed the Despoiler*, *Rhapsody's Embrace*, *Veil Render*, *NO-AH-5*, *Infested Apostle*—requiring a `TARGET_ROLE_SACRIFICE_COST` target binding). `CostDef` has no `selector: "SELF"` field or `KILL_SELF` enum to distinguish self-sacrifice from allied-asset sacrifice.
  - **Exploit / Failure Scenario:** Encoding `"T1, kill this unit"` on *Sinuous Growth* as `costType: "KILL_ASSET"` with `filter: { allegiance: "ALLIED", entityType: "UNIT" }` either requires a `TARGET_ROLE_SACRIFICE_COST` binding on the wire or allows *Sinuous Growth* to sacrifice a different allied unit instead of itself.
  - **Remedy:** In `FR-ABL-007`, standardize `CostDef.costType` on `KILL_SELF` (kills the host asset itself; no target binding required) and `KILL_ASSET` (kills a chosen allied asset matching `filter`; bound via `TARGET_ROLE_SACRIFICE_COST`), removing the redundant `SACRIFICE_ALLY` enum, and synchronize `EXHAUST_ASSET` between `FR-ABL-007` and `05_Headless_Game_Engine_FRD.md` (`FR-ENG-013`).

### 🟡 Medium
- **[DA-DAT-004] [Conflict] Non-Existent Replacement Opcodes Cited in FR-ABL-005 and Inconsistent Target / Duration Schema Definitions in FR-PRM-001**
  - **Requirement Citations:** `FR-ABL-005`, `FR-ABL-007`, `FR-PRM-001`
  - **Vulnerability / Flaw:**
    1. `FR-ABL-005` (line 208) states that `ReplacementWatcherDef.replacementAction` is an `EffectDef` and cites `SET_INITIAL_READINESS` and `CANCEL_AND_BOUNCE` as example primitives. However, `FR-ABL-007` requires `EffectDef.primitive` to match `FR-PRM-001`, and neither `SET_INITIAL_READINESS` nor `CANCEL_AND_BOUNCE` exists in `FR-PRM-001`.
    2. In `FR-PRM-001`, `PUT_CARD_ON_DECK` names its target parameter `targetCard: TargetRef` and `EXHAUST` names its target parameter `targetAsset: TargetRef`, conflicting with `EffectDef` in `FR-ABL-007` (which defines the standard property `target: TargetRef` used across `02_Benchmark_Card_Blueprints.md`). Additionally, `MODIFY_STAT` in `FR-PRM-001` lists lowercase `persistent` alongside uppercase `END_OF_TURN` and `END_OF_OPPONENT_TURN` and leaves `attribute: Enum` unconstrained (`COMBAT_POWER`, `MAX_HEALTH`).
  - **Exploit / Failure Scenario:** `AbilityDef.schema.json` (`FR-CMP-022`) will reject `EffectDef` nodes that use `target` on `PUT_CARD_ON_DECK` / `EXHAUST` or fail when attempting to resolve the non-existent `SET_INITIAL_READINESS` and `CANCEL_AND_BOUNCE` opcodes.
  - **Remedy:** Replace the non-existent `SET_INITIAL_READINESS` and `CANCEL_AND_BOUNCE` examples in `FR-ABL-005` with canonical `FR-PRM-001` primitives (`EXHAUST`, `RETURN_TO_HAND`, `DEAL_DAMAGE`), standardize `PUT_CARD_ON_DECK` and `EXHAUST` in `FR-PRM-001` to use `EffectDef.target`, and specify `attribute: Enum [COMBAT_POWER, MAX_HEALTH]` and uppercase `PERSISTENT` on `MODIFY_STAT`.

- **[DA-DAT-005] [Conflict] Optional vs. Unconditional Serialization of currentProxy and needsRework Across FR-DAT-005, FR-CMP-005, and Benchmark Blueprints**
  - **Requirement Citations:** `FR-DAT-005`, `FR-VAL-003`
  - **Vulnerability / Flaw:** `FR-DAT-005` (lines 108, 127–128) defines `currentProxy` and `needsRework` as **optional** fields excluded from the `required` array of `CardBlueprint` (and all 14 benchmark blueprints in `reference/02_Benchmark_Card_Blueprints.md` omit them), whereas `FR-CMP-005` in `03_Card_Compiler_FRD.md` (line 135) states that `currentProxy` and `needsRework` serialize directly onto the `CardBlueprint` from CSV.
  - **Exploit / Failure Scenario:** Because `catalogChecksum` (`FR-CMP-024`) computes a SHA-256 digest over the RFC 8785 canonical JSON of `blueprints`, including vs. omitting `currentProxy` and `needsRework` alters `catalogChecksum`, and toggling `currentProxy` or `needsRework` on a card would invalidate live client-server handshakes and historical `.rec` replays (`FR-DAT-004`).
  - **Remedy:** Clarify in `FR-DAT-005` and `FR-CMP-005` whether `currentProxy` and `needsRework` are always required on `CardBlueprint` (and excluded from RFC 8785 `catalogChecksum` hashing) or omitted when `false`.

### 🔵 Low / Clarification
- **[DA-DAT-006] [Redundancy] Redeclaration of Canonical Game Rules from FRD 01 in FR-TRG-001, FR-ABL-002, and FR-TXT-004**
  - **Requirement Citations:** `FR-TRG-001`, `FR-ABL-002`, `FR-TGT-101`, `FR-TXT-004`
  - **Vulnerability / Flaw:** `02_Card_Data_Pipeline_FRD.md` redeclares normative game rules already canonically specified in `01_Game_Rules_FRD.md`:
    1. `FR-TRG-001` (line 240) redeclares attacker-only combat-kill rules vs. defender retaliation (canonically defined in `FR-CBT-002`).
    2. `FR-TXT-004` (line 389) redeclares two-stage dynamic target verification and fizzle rules (canonically defined in `FR-TGT-003`).
    3. `FR-ABL-002` (line 184) and `FR-TGT-101` (line 285) duplicate the upfront target binding rules (canonically defined in `FR-TGT-001`).
  - **Exploit / Failure Scenario:** Duplicate normative prose across FRD 01 and FRD 02 risks divergence when rules are revised.
  - **Remedy:** Replace the duplicated rules prose in `FR-TRG-001`, `FR-ABL-002`, and `FR-TXT-004` with concise references to `FR-CBT-002`, `FR-TGT-001`, and `FR-TGT-003` in `01_Game_Rules_FRD.md`.
